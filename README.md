# Hi, I'm Victor.

I'm a software engineer based in Costa Rica. I build web applications and tools, and I write about the experiments behind them.

I like taking a problem apart, building something useful, and writing down what I learned. [Vagancia Project](https://vaganciaproject.com) is where I share that process, in English and Spanish.

*Observe. Investigate. Create.*

## Selected work

### [Vagancia Fitness](https://github.com/kno-raziel/vagancia-fitness)

*Created: October 2026*

I'm building Vagancia Fitness for my treadmill workouts on iPhone and Apple Watch. I'm bringing workout tracking, HealthKit integration, and Bluetooth diagnostics into native apps with a shared protocol core and local storage. It's a personal project, available as source code to build locally.

Swift · SwiftUI · CoreBluetooth · HealthKit · SQLite

### [Sand Canvas](https://github.com/kno-raziel/sand-canvas)

*Started: February 25, 2026*

I built Sand as an open-source experiment in visual collaboration with AI coding agents, using real React components and MCP. The exercise helped me realize that my existing Storybook setup already covered my workflow, so I didn't need Sand or Figma for my personal projects.

React · TypeScript · MCP · Zod

[Read how I reached that conclusion](https://vaganciaproject.com/blog/sand-poc/).

### [Spectral Curiosity](https://github.com/kno-raziel/spectral-curiosity)

*First commit: March 16, 2026*

I built Spectral when I wanted to leave Antigravity and take my work with me. I needed conversations, generated plans, documentation, and images collected in bulk. Its extension backs up the available data, and a standalone app lets me browse and search the archive outside Antigravity.

React · TypeScript · Bun · SQLite

[Read why I built it](https://github.com/kno-raziel/spectral-curiosity#why-spectral).

## How I work

I use coding agents for implementation, debugging, and review. I guide the work with repository instructions, scoped tasks, and acceptance criteria, then inspect the changes and verify behavior with tests. I want to understand the decisions well enough to maintain what I build.

In my latest React projects, I've switched from Storybook to [React Cosmos](https://reactcosmos.org/). Its plain React fixtures are a better fit for how I explore component states and interactions in isolation.
